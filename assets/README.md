# 品牌素材

不参与构建，也不进发行包（打包只安装编译产物与 `data/*`）。放在仓库里是为了让 logo 与
它所描述的界面一起被版本管理——界面改了，这里的还原也该跟着改。

| 文件 | 用途 |
|---|---|
| `logo.svg` | 主标记。原生 16px 网格，墨色 `#5E7B78`、强调色 `#2FB8A8`，两个都是固定值 |
| `logo-256.png` / `logo-512.png` | 同一个标记的透明底位图，给不接受 SVG 的地方（OBS 论坛资源页等）|
| `social-card.html` | GitHub social preview 源文件，1280×640 |
| `social-card.png` | 上面那个的渲染结果，直接上传到仓库 Settings → Social preview |

## 重新生成 PNG

```bash
chrome --headless --disable-gpu --hide-scrollbars \
       --screenshot=assets/social-card.png --window-size=1280,640 \
       assets/social-card.html
```

logo 位图同理，把 SVG 放进一个等尺寸的空页面再截，加 `--default-background-color=00000000` 保留透明。
**改完回头查一遍像素**：截出来的两张图里只该有 `#5E7B78` 和 `#2FB8A8` 两种不透明色，
字节数和旧图撞上是正常的（形状与 alpha 没变，只换了调色板），别拿它当没生效的证据。

## 设计依据

**标记**：左侧竖脊是树的缩进导引线，右侧三条行是一个父项带两个缩进子项，最下面那条带强调色
——构成即产品本身。"锚"落在这条导引线上，不画船锚。

另测过三种方案并全部否掉，都是因为 **16px 下糊成一团**：方括号加两个方块、极简单竖线加一个色块、
文件夹造型加下挂行。选中的这版是唯一在 16/24/32/64 全尺寸、深浅两种底色上都读得出层级的。

**墨色不用 `currentColor`。** 这个**文件**只被 `<img>` 引用（README 两份、论坛资源页），
而 `<img>` 里的 SVG 是独立文档，`currentColor` 拿不到宿主的前景色、只会落到默认的黑——
2026-08-18 实测正是如此：GitHub 暗色主题下整个标记消失，只剩那条青色强调条浮在深底上。
换成固定的 `#5E7B78`：对白底 4.6:1、对 GitHub 暗底 `#0d1117` 4.1:1，都过图形元素 3:1 的下限，
色相偏向 `#2FB8A8` 因而与强调色同族。**改这个值之前，先在浅底与深底各渲一次再看。**

social card 是例外，别顺手把它一起改：那边把同一份路径数据**内联**进 HTML，
内联 SVG 会正常继承 `.brand` 的 `color`，`currentColor` 在那个语境下是对的。
两处形状同源但不共享文件——改了标记的几何，两边都要动。

**social card**：不做「logo + 渐变底 + 大标题」那套通用卡。右半边是插件真实界面的忠实还原——
OBS 用户一眼认得那个 dock，比任何抽象图形都说明问题，而且它诚实：卡上画的就是装完之后看到的东西。
左半边只放名字、slogan 和三条**可验证**的事实，不写"最强""最好用"这类无法证伪的话。

> **「忠实还原」是要维护的承诺，不是一次性的。** 2026-08-18 这张卡上还画着「Main canvas」「Vertical canvas」两条画布分区标题行，而那个功能当天已被整个删除——卡上画着一个不存在的界面，比画得抽象更糟。**改过 dock 的渲染就回来核一遍这张卡**：行的缩进、展开箭头的样子、dock 标题的写法、有没有已经不存在的行类型。右半边是手绘 HTML 而不是截图，正是因为信息流缩略图尺寸下真截图的细节全糊；代价就是它不会跟着代码自动更新。

底色 `#272A33` 不是随手挑的深色，是从真机截图里取到的树视图实际背景色（同一个值也是
颜色标签对比度自适应的计算基准，见 `src/tree_dock.cpp` 的 `contrastAdjusted`）。

**强调色 `#2FB8A8`**（青绿）刻意不在颜色标签的八个预设里——品牌色与用户数据的标签色分属两套，
免得用户以为那是某个可选标签。
