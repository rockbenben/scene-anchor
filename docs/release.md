# SceneAnchor 发布流程

## 版本与 tag

- **tag 必须是裸 `X.Y.Z`，不加 `v`。** 预发布用 `X.Y.Z-betaN` 或 `X.Y.Z-rcN`。
  现有 `1.0.0`、`1.0.1` 都是这个格式，OBS 插件模板的发布正则也只认裸版本号；
  `v1.0.2` 会被 CI 直接拒绝并提示正确写法。
- **tag 必须等于 `buildspec.json` 的 `version`。** `check-event` 在构建前比较两者，
  不一致就失败，避免 `1.0.2` 的 tag 发出 `1.0.1` 的文件。
- **OBS 32 兼容的最后一版是 `1.0.1`。** 从下一个版本起只支持 OBS 33+、只发 OBS 33 的
  插件目录；放弃 OBS 32 是破坏性变更，版本号应为 `2.0.0`。

## 发版步骤

1. 改 `buildspec.json` 的 `version`。破坏性支持范围变化抬 major。
2. 更新 `README.md` / `README.zh.md` 的支持范围、安装路径与已知限制；按
   [`docs/pre-release-checklist.md`](pre-release-checklist.md) 在目标 OBS 版本上跑完整清单。
3. 本地验证：构建、单测、安装布局、OBS 实机加载。
4. 提交后打 tag，推送 tag：

   ```bash
   git tag 2.0.0
   git push origin 2.0.0
   ```

5. CI 依次执行：单测 → 三平台构建/打包 → `create-release` 生成 draft release。
   单测失败时不会创建 release。
6. 检查 draft 的产物与 `CHECKSUMS.txt`，用下面的模板补中英双语说明，再发布。
   draft 初始正文只有校验和；在它上面加说明，不要删掉校验和块。
7. 发布后把 OBS 论坛资源页的版本与下载链接更新到新 release。

## 发布产物

| 平台 | 文件 | 安装位置 |
|---|---|---|
| Windows | `scene-anchor-<version>-windows-x64-Installer.exe` / `.zip` | 常规安装：`C:\ProgramData\obs-studio\plugins\scene-anchor\`；便携版：`<OBS>\plugins\scene-anchor\` |
| macOS 13+ | `scene-anchor-<version>-macos-universal.pkg` | `/Library/Application Support/obs-studio/plugins/scene-anchor.plugin` |
| Ubuntu 26.04 | `scene-anchor-<version>-x86_64-linux-gnu.deb` | `/usr/lib/<multiarch>/obs-modules/plugins/` + `/usr/share/obs/obs-modules/plugins/` |
| 调试/源码 | `-dbgsym.ddeb`、`-source.tar.xz` | 普通用户不需要 |

## OBS 插件发布渠道

- **GitHub Releases 是唯一权威下载源。** CI 自动建 draft，人工发布。
- **OBS 论坛 Resources 是官方的发现入口。** 本项目已有资源页
  <https://obsproject.com/forum/resources/sceneanchor.2666/>；新版本发布后更新版本号、
  下载链接、兼容范围与更新说明。
- **没有应用商店式提交。** `obsproject.com/plugins` 已不存在；OBS 33 的插件管理器只管理
  本机已安装插件，没有第三方仓库或提交 API。不要等待「上架」再发布。
- winget / AUR / Flathub 属于额外分发渠道，不是官方渠道；要做另开任务，不混进 Release 流程。
